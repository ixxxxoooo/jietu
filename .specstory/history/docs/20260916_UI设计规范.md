# Jietu UI 设计规范（对齐 Tinycast 组件风格）

> 来源：`~/tinycast` 的 `Tinycast/DesignSystem/`（`Theme.swift` 为唯一 token 源，
> `docs/ui.md` 为叙述版规范）。本文件把该风格落到 Jietu 的界面上。
>
> 适用范围：**全部 SwiftUI 内容界面**（设置页、权限引导、QAO 浮窗、就地标注工具栏、
> 标注编辑器工具栏、历史面板、滚动长图控制条）。
> AppKit 遮罩画布（`OverlayCanvasView`）只复用颜色 / 尺寸 token，不改分层结构。

---

## 1. 五条承重规则

1. **表面 = 磨砂 + 墨色 scrim。** 不用实心灰底；深色下黑 40%、浅色下白 55% 压一层，
   底下是 behind-window 的 `NSVisualEffectView`。
2. **只有一条 alpha ramp，不用灰。** 深色底上是白墨、浅色底上是黑墨，
   alpha 停在固定档位。所有"次要色/分隔线/控件底"都从这条 ramp 取值。
3. **浮动条不是 chrome。** 工具栏 / 底部操作区是悬浮在内容之上的透明层，
   没有硬边、没有分隔条。
4. **边角是"溶解"，不是"裁切"。** 列表在边缘用渐变遮罩淡出（`EdgeDissolve` / `OverflowFade`）。
   Jietu 的滚动列表沿用（历史面板缩略图列表）。
5. **玻璃只给浮动控件。** 主表面永远不是 glass；只有胶囊按钮、圆形按钮、
   搜索框这类"浮在表面上的控件"用 `glassEffect`。

## 2. 设计令牌（Design Tokens）

全部定义在 `Jietu/UI/DesignSystem/Theme.swift`。

### 2.1 颜色：一条 alpha ramp

```swift
Theme.Colors.adaptive(dark:light:)   // 按 effectiveAppearance 实时解析
Theme.Colors.ramp(dark:light:)       // 深色白墨 / 浅色黑墨
```

| Token | 深色 | 浅色 | 用途 |
|---|---|---|---|
| `panelScrim` | black α0.40 | white α0.55 | 面板 / 浮窗 / 工具栏的压底 |
| `selection` | white α0.10 | black α0.09 | 选中行填充 |
| `rowHover` | white α0.05 | black α0.045 | 行悬停（永远比选中更淡） |
| `menuHover` | white α0.10 | black α0.09 | 菜单行悬停 |
| `separator` | white α0.10 | black α0.12 | 列表↔预览的 1px 细线 |
| `controlSurface` | white α0.10 | black α0.08 | 填充 keycap、分段控件选中底、字形块 |
| `border` | white α0.20 | black α0.18 | 描边 keycap 边框 |
| `textPrimary` | white α1.00 | black α1.00 | 主文本 / 数值 |
| `textSecondary` | white α0.60 | black α0.60 | 次级标签 |
| `textTertiary` | white α0.40 | black α0.42 | 占位符 / 尾部弱标签 |
| `iconPlaceholder` | white α0.06 | black α0.06 | 图标解码前的空块 |
| `cardFill` | white α0.05 | black α0.04 | 设置卡片底 |
| `cardStroke` | white α0.10 | black α0.10 | 卡片描边（同时兼作行分隔） |
| `glassFrost` | white α0.05 | white α0.25 | 玻璃色调（明暗都是白） |

功能色（不属于 ramp，Jietu 语义专用）：

| Token | 值 | 用途 |
|---|---|---|
| `accent` | `Color.accentColor`（= `AccentColor` 资产 = `#0D44E8`） | **统一强调色**：图标、开关打开态、分段/单选选中态、聚焦环 |
| `icon` | `accent` | 图标统一颜色（侧栏 / 设置行 / 工具条都取它） |
| `brand` | `accent` | Jietu 品牌蓝，与强调色同源 |
| `selectionGreen` | RGB(0.14,0.87,0.45) | 截图选框 / 控制点（功能色，不可替换） |
| `destructive` | `Color.red` | 取消 / 删除 |
| `success` | `Color.green` | 完成 / 已授权 |
| `warning` | `Color.orange` | 未授权 / 冲突提示 |
| `progress` | `Color.blue` | 进行中 |

> **图标只取一处颜色**：参考项目里图标配色也只从单一 token 取
> （`menuSymbol` / `Color.accentColor`），只有功能状态才破例（`.success` / `.warning` /
> `.destructive`）。**不逐分区换色**——统一配色指的是"同一处来源、同一个颜色"。

> `overlayDimAlpha = 0.45` 是选区外压暗程度，属于遮罩画布的功能参数，保留在 `Theme` 顶层。

### 2.2 间距 `Theme.Spacing`

`xxs 2` / `xs 4` / `sm 6` / `md 8` / `lg 10` / `xl 12` / `xxl 20` / `xxxl 28`

- 行内边距 `md`(8)；列表水平内边距 `md`；区块间距 `sectionSpacing 12`；
  区块标题下间距 `sectionHeaderBottom 4`。

### 2.3 圆角 `Theme.Radius`（全部 `style: .continuous`）

| Token | 值 | 用途 |

| `dialog` | 20 | 对话框 / 浮窗表面 |

| `card` | 10 | 设置卡片 / 普通卡片 |
| `row` | 10 | 列表行悬停底 |

## 3. 组件规范

### 3.1 `VisualEffectView`

`NSVisualEffectView` 的 SwiftUI 桥（`material` + `blending`）。
**不锁 `.darkAqua`**，跟随窗口外观；表面自身的明暗由 `panelScrim` 决定。

### 3.2 表面 `FloatingSurface`

浮动条 / 浮窗的统一表面：`VisualEffectView(.hudWindow)` + `Theme.Colors.panelScrim`
+ `Radius`。可叠加 1px `border` 描边（仅当需要从背景里"浮"出来时）。
替代原有的 `FrostedBar`。

### 3.3 `BarButton` / `BarButtonChrome`

工具条控件：**默认裸露，悬停才出现胶囊/圆角高亮**（`rowHover` 填充）。
`chrome` 取 `.capsule`（底部操作组）或 `.rounded`（`Radius.barControl`，顶部下拉）。

### 3.4 `KeyCapChip`

单个按键芯片：`.outline`（描边，行的热键提示）/ `.filled`（填充，底栏快捷键）。
三档 `Scale`：`.compact 15` / `.standard 18` / `.hero 22`；圆角 `Radius.keyCap 6`；
字色 `textSecondary`。

### 3.5 设置组件

- `SettingsCard`：`cardFill` 底 + `cardStroke` 描边 + `Radius.card`，行之间用 cardStroke 内分隔。
- `SettingsRow`：`图标 · 标题/副标题 · 尾部控件`，间距 `Spacing.lg`；副标题 `.caption` + `textSecondary`。
- `SettingsToggleRow` / `SettingsControlRow`：带 `SettingsIcon` 图标槽的开关行 / 控件行，
  设置页每一行都用它们，图标统一 `Theme.Colors.icon`。
- `SettingsIcon`：固定 `settingsRowIcon 20` 的图标槽，默认色 = `icon`（功能状态可传
  `success` / `warning` 破例）。
- `SettingsSectionHeader`：`.subheadline.weight(.medium)` + `textSecondary`。
- `settingsEnabled(_:)`：`.disabled` 同时降到 0.45 透明度。

### 3.6 快捷键录制器（一个组件干完录制与清除）

`HotkeyRecorderView` 是**自包含**控件：固定 `120×24` 的槽（`Radius.menu`，
`cardFill` / `cardStroke`，录制中描边 `accent`），三种内容：

| 状态 | 内容 |
|---|---|
| 未绑定 | 「未设置」`textTertiary`（悬停转 `textSecondary`） |
| 录制中 | 「请按组合键…」`textSecondary` |
| 已绑定 | 逐键 keycap（`recorderKeyCap 16` / `Radius.recorderKeyCap 4` / `controlSurface`），**悬停时右侧浮出 `xmark.circle.fill` 清除** |

- 清除**不单独摆按钮**：它就是录制器的一部分（参考项目的 `ShortcutRecorder` 同理）。
- `Hotkey.keycaps` 把组合键拆成逐个芯片；`HotkeyAction.symbol` 给每行提供图标。

### 3.7 玻璃控件

`View.frosted(in:)`：`glassEffect(.regular.interactive().tint(glassFrost), in:)` + `.tint(.clear)`。
只用于胶囊/圆形浮动按钮，**不用于主表面**。

## 4. 界面映射（Jietu 各界面 → token / 组件）

| 界面 | 表面 | 组件要点 |
|---|---|---|
| **设置页** `SettingsView` | 窗口 `settingsWindow`；侧栏 `List(.sidebar)`；详情 `Form(.grouped)` | `SettingsSectionHeader` + `SettingsToggleRow` / `SettingsControlRow`；图标统一 `icon`；`.tint(accent)` 统一开关与选中态 |
| **快捷键录制** `HotkeyRecorderView` | `SettingsRow` 尾部，自包含 | 见 3.6：录制 + 悬停清除同属一个控件，无独立「清除」按钮 |
| **权限引导** `OnboardingView` | `panelScrim` + blur，`Radius.dialog` | `dialogIcon 32` 品牌色字形；授权状态卡 `cardFill/cardStroke`；主按钮玻璃胶囊，`success/warning` 状态色 |
| **QAO 浮窗** `QuickAccessView` | 卡片 `panelScrim` + blur，`Radius.menuPanel`；悬停加深 | 图片上浮四角圆形玻璃钮 + 居中胶囊玻璃钮；选中边框用 `brand` |
| **就地标注工具栏** `InlineAnnotationToolbar` | 浮动条 `FloatingSurface`，`Radius.menuPanel` | 工具按钮选中 → `controlSurface` 填充 + `textPrimary`；未选中 `textSecondary`；分隔线 `separator` |
| **标注编辑器工具栏** `AnnotationEditorView` | 非就地：`contentBackground` 窗底；就地：浮动条 | 同就地工具栏；缩放控件用 `KeyCapChip`/`bar` 字体 |
| **历史面板** `HistoryView` | `panelScrim` + blur，`Radius.dialog` | 头部 `sectionHeader`+尾部玻璃小按钮；缩略图 `Radius.thumbnail` + `border` 描边 |
| **滚动长图控制条** `ScrollingCapturePanelView` | 浮动条 `panelScrim` + blur，`Radius.menuPanel` | 进度用 `Typography.numeric`；底部 `.capsule` 玻璃按钮组 |
| **遮罩画布** `OverlayCanvasView` | 不变（CALayer） | 复用 `Colors.selectionGreen` / `overlayDimAlpha` / `Size.selectionHandleSize` |

## 4.1 构建渠道（Debug = dev）

Debug 是独立渠道，Debug 配置里 `PRODUCT_NAME = "Jietu Dev"`、
`PRODUCT_BUNDLE_IDENTIFIER = com.liwenjiao.jietu.dev`、`PRODUCT_MODULE_NAME = Jietu`
（固定，否则 `@testable import Jietu` 会断），`JietuTests` 的 `TEST_HOST` 同步指向
`Jietu Dev.app/Contents/MacOS/Jietu Dev`。

- 独立 bundle id = 独立 TCC 授权 / 偏好 / 登录项，本地调试不污染正式版。
- `AppIdentity`（`Core/AppIdentity.swift`）暴露 `displayName` / `isDevChannel` /
  `bundleIdentifier`；设置页「权限 › 授权对象」与权限引导都会显示当前身份，
  dev 渠道额外带一个 `accent` 描的 **dev** 药丸，照着在系统设置里勾选即可。
- `Config/Info.plist` 的 `CFBundleDisplayName = $(PRODUCT_NAME)`，所以系统设置的
  「屏幕录制」列表里 Debug 显示为 **Jietu Dev**。

## 5. 有意省略（相对 Tinycast）

- **InterfaceMetrics 缩放**：Jietu 没有「界面尺寸」设置，不引入缩放层；
  组件直接读 `Theme`。
- **PopoverMenu / CommandPalette / EdgeDissolve 全套实现**：Jietu 无对应交互，
  只保留历史面板需要的边缘渐变淡出做法。
- **品牌色**：保留 Jietu 蓝 `#0D44E8`，不套用 Tinycast 紫 `#863BFF`。

---

## 6. 代码约定

- 所有新组件放 `Jietu/UI/DesignSystem/`，命名与 Tinycast 保持一致
  （`Theme` / `VisualEffectView` / `BarButton` / `KeyCapChip` / `SettingsComponents`）。
- 数值一律走 token，不在视图里写魔法数（AppKit 画布的功能参数除外）。
- 圆角一律 `style: .continuous`。
- 每个文件加 `@author ixxxxoooo`；方法写用途注释。
