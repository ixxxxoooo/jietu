# Jietu UI 设计规范（对齐 Tinycast 组件风格）

> 来源：`~/tinycast` 的 `Tinycast/DesignSystem/`（`Theme.swift` 为唯一 token 源，
> `docs/ui.md` 为叙述版规范）。本文件把该风格落到 Jietu 的界面上。
>
> 适用范围：**全部 SwiftUI 内容界面**（设置页、权限引导、QAO 浮窗、原地标注工具栏、
> 标注编辑器工具栏、历史面板、滚动长图控制条）。
> AppKit 遮罩画布（`OverlayCanvasView`）只复用颜色 / 尺寸 token，不改分层结构。

---

## 1. 五条承重规则

1. **表面 = 磨砂 + 墨色 scrim。** 不用实心灰底；深色下黑 40%、浅色下白 55% 压一层，
   底下是 behind-window 的 `NSVisualEffectView`。
2. **只有一条 alpha ramp，不用灰。** 深色底上是白墨、浅色底上是黑墨，
   alpha 停在固定档位。所有"次要色/分隔线/控件底"都从这条 ramp 取值。
3. **浮动条不是 chrome。** 工具栏 / 底部操作区是悬浮在内容之上的透明层，
   没有硬边、没有分隔条。
4. **边角是"溶解"，不是"裁切"。** 列表在边缘用渐变遮罩淡出（`EdgeDissolve` / `OverflowFade`）。
   Jietu 的滚动列表沿用（历史面板缩略图列表）。
5. **玻璃只给浮动控件。** 主表面永远不是 glass；只有胶囊按钮、圆形按钮、
   搜索框这类"浮在表面上的控件"用 `glassEffect`。

## 2. 设计令牌（Design Tokens）

### 2.1 颜色：一条 alpha ramp


## 3. 组件规范

### 3.1 `VisualEffectView`

`NSVisualEffectView` 的 SwiftUI 桥（`material` + `blending`）。
**不锁 `.darkAqua`**，跟随窗口外观；表面自身的明暗由 `panelScrim` 决定。

### 3.2 表面 `FloatingSurface`

浮动条 / 浮窗的统一表面：`VisualEffectView(.hudWindow)` + `Theme.Colors.panelScrim`
+ `Radius`。可叠加 1px `border` 描边（仅当需要从背景里"浮"出来时）。
替代原有的 `FrostedBar`。

### 3.3 `BarButton` / `BarButtonChrome`

工具条控件：**默认裸露，悬停才出现胶囊/圆角高亮**（`rowHover` 填充）。
`chrome` 取 `.capsule`（底部操作组）或 `.rounded`（`Radius.barControl`，顶部下拉）。

### 3.4 `KeyCapChip`

单个按键芯片：`.outline`（描边，行的热键提示）/ `.filled`（填充，底栏快捷键）。
三档 `Scale`：`.compact 15` / `.standard 18` / `.hero 22`；圆角 `Radius.keyCap 6`；
字色 `textSecondary`。

### 3.5 设置组件

`SettingsComponents.swift` 只留**多个面板共用**的几件（对齐参考项目的收束）：

- `SettingsRow`：`标题 / 副标题 + 尾部自定义控件`，间距 `Spacing.lg`，
  副标题 `.caption` + `secondary`、两行、中间截断、带 `.help`。
  **只用于尾部是自定义控件的行**（录制器 / 滑块 / 按钮组）；普通设置行用 stock 控件（见 4.0.1）。
- `SettingsSectionHeader`：`.subheadline.weight(.medium)` + `textSecondary`。
- `SettingsCard`：`cardFill` 底 + `cardStroke` 描边 + `Radius.card`（权限引导的状态卡在用）。
- `DevChannelBadge`：`accent` 色 `dev` 药丸，标出当前是 Debug 渠道。
- `settingsEnabled(_:)`：`.disabled` 同时降到 0.45 透明度。

### 3.6 快捷键录制器（一个组件干完录制与清除）

`HotkeyRecorderView` 是**自包含**控件：固定 `120×24` 的槽（`Radius.menu`，
`cardFill` / `cardStroke`，录制中描边 `accent`），三种内容：

| 状态 | 内容 |
|---|---|
| 未绑定 | 「未设置」`textTertiary`（悬停转 `textSecondary`） |
| 录制中 | 「请按组合键…」`textSecondary` |
| 已绑定 | 逐键 keycap（`recorderKeyCap 16` / `Radius.recorderKeyCap 4` / `controlSurface`），**悬停时右侧浮出 `xmark.circle.fill` 清除** |

- 清除**不单独摆按钮**：它就是录制器的一部分（参考项目的 `ShortcutRecorder` 同理）。
- `Hotkey.keycaps` 把组合键拆成逐个芯片；`HotkeyAction.symbol` 给每行提供图标。

### 3.7 玻璃：控件 vs 面板表面（两种，别混用）

| 用途 | API | 配方 |
|---|---|---|
| **控件**（胶囊 / 圆 / 可拖拽卡片） | `View.frosted(in:)` | `glassEffect(.regular.interactive().tint(glassFrost), in:)` + `.tint(.clear)` |
| **浮动面板表面**（popover / 浮动小窗） | `View.glassPanel(cornerRadius:)` | `glassEffect(.regular, in: RoundedRectangle(Radius.menuPanel, .continuous))` + `.clipShape` |

- 面板表面用**静态 `.regular`**：不加 `interactive`（面板本身不该有按下反馈）、不加 tint、
  **不描边**。参考项目的 `PopoverMenu` / `NoteSwitcherView` / `ExtensionActionsPanel`
  都是这个配方；`frosted` 那套是给控件的。
- 主表面（palette / 设置 / 引导）永远用 `FloatingSurface`（磨砂 + `panelScrim`），
  **不用玻璃**；`glassEffect` 只出现在浮在屏幕内容之上的东西上。
- 玻璃面板里的「槽」（如拖拽卡片）压一层 ramp 的 `controlSurface` 即可，
  不要描边、不要引入灰。
- **面板阴影一律用系统窗口阴影**：`NSPanel.hasShadow = true`，内容保持圆角 + 透明窗口，
  AppKit 按内容 alpha 画出贴合形状的阴影；进场动画结束后补一次 `invalidateShadow()`
  （AppKit 会按首次绘制的 frame 缓存并缩放阴影）。**不要给面板表面挂 SwiftUI `.shadow`**——
  参考项目里 `.shadow` 只用在「关于页的 App 图标」这类装饰上。

**主表面永远取系统材质，不手绘描边。** 浮窗（QAO）悬停时也不描彩边：
只用 `border` 换掉 `cardStroke` 的一根细边，压深程度交给 macOS 的玻璃自己画。

## 4.0 设置窗口的 chrome 与材质（最容易做错的一节）

设置窗是**唯一保留系统标题栏**的窗口，四条规则缺一不可：

1. **窗口 styleMask**：`[.titled, .closable, .miniaturizable, .resizable, .fullSizeContentView]`。
   少了 `.miniaturizable` / `.resizable`，黄绿两个灯就是灰的、点不动。
2. **标题栏**：建窗时按浮窗习惯 `titlebarAppearsTransparent = true`，
   再由 chrome 设回 `false` + `titleVisibility = .visible` + `toolbarStyle = .unified`
   + `titlebarSeparatorStyle = .none` + `isMovableByWindowBackground = false`。
   这样玻璃带与「表单滚到栏下」的边缘效果由 AppKit 画，且一条细线也不会把表面切两半。
3. **侧栏材质**：必须 `NSSplitViewController` + `NSSplitViewItem(sidebarWithViewController:)`
   （固定 `settingsSidebar 215`、`canCollapse = false`），两列都要
   `.scrollContentBackground(.hidden)`，否则拿不到系统 sidebar 材质。
   SwiftUI 的 `NavigationSplitView` 做不到这件事。
   **侧栏图标只在未选中时给 `icon` 色**；选中态不给颜色，交回系统——
   选中底色有两种（侧栏有焦点=强调蓝、无焦点=浅灰），只有系统知道该配白字还是标签色，
   自己写死任何一种都会在另一种情况下看不见。
4. **分区标题不在面板里**：`SettingsToolbarController`（AppKit `NSToolbar`，不是 SwiftUI `.toolbar`）
   把它放在标题栏，用 `.sidebarTrackingSeparator` 定位到分区列；
   标题同步 `window.title`，靠 `withObservationTracking` 监听导航状态。

**工具栏的「回退 / 前进」**：两个独立 `NSButton`（不是 segmented，后者中间会有分隔线），
`bezelStyle = .toolbar`，item 上 `isNavigational = true`（把按钮排到内联标题之前）、
`autovalidates = false`（可用性来自导航历史，而不是响应链）。图标用方向性的
`chevron.backward` / `chevron.forward`，RTL 下自动镜像。

**导航历史**：`SettingsNavigationState`（`@Observable`）持当前分区 + 回退 / 前进栈，
只属于这一个窗口，窗口关掉即释放。侧栏点选走 `select(_:)`，因此回退 / 前进能走一遍。

### 4.0.1 设置行的写法（副标题样式就来自这里）

- **一行就是一个 stock 控件**：`Toggle` / `Picker` / `LabeledContent`，
  label 用**两段式**——第一段是标题，其余自动成为次级副标题。
  副标题的字号 / 颜色 / 换行全部由系统按分区表单的规格给。**绝不自己拼 HStack。**
- **尾部是自定义控件**（滑块 + 读数、按钮组、快捷键录制器）的行才用 `SettingsRow`
  （不用 `LabeledContent`：它的可选中文本框会吃掉录制器需要的点击）。
- **状态 / 数值行用 `LabeledContent`**，字形放尾部（`Label(_, systemImage:)`），
  标题那侧只有文字。设置行**没有前导图标槽**——参考项目里行不带图标，只有侧栏有。
- **`.settingsEnabled(_:)` 而不是裸 `.disabled(_:)`**：它会同时压暗，被关掉的行读起来是
  「不可用」而不只是「点了没反应」。
- 一组设置就是一个 `Section`，名字给 `header:`、说明给 `footer:`
  （footer 显式 `.font(.caption).foregroundStyle(.secondary)`）。
- 设置窗全局 `.tint(Theme.Colors.accent)`，开关打开态 / 分段 / 单选 / 聚焦环同一来源。

## 4.1 外观（主题）

`AppAppearance`（`Core/Settings/AppAppearance.swift`）：`system` / `light` / `dark`，
`system` 的 `nsAppearance` 返回 `nil`，把选择交还 AppKit（改系统外观时无需重启即刻跟随）。
`SettingsStore.appearance` 持久化；启动时 `AppDelegate` 调一次 `.apply()`，
设置页里 `.onChange` 再调一次，整进程（所有窗口）一起变。

## 4.6 截图浮窗（QAO）

`QuickAccessView` 的设计取向是「**截图本身是视觉主体**」，别再套一层厚重卡片：

| 规则 | 做法 |
|---|---|
| 尺寸 | `panelSize(for:)` 按截图原始宽高比等比缩放，只受 `Size.quickAccessCardMax`（260×180）上限；**永不拉伸**，也不 letterbox |
| 尺寸自适应 | 面板 frame = 卡片尺寸；叠放时每张按**自己的高度**占位（不重叠） |
| 交互一致 | 卡片大小不改变交互：点击进标注、拖拽导出、四角/中央按钮位置一致 |
| 静息态 | 只有截图本身，**不显示任何按钮** |
| 悬停态 | 截图 `blur(16)` 露出底下的毛玻璃（**不压色、不缩放**），操作层浮在截图之上 |
| 底色 | `glassPanel()`：后方色彩模糊的玻璃；透明 PNG / 悬停模糊时才透出来 |
| 白边 | 极细内描边：`border`/`cardStroke` 的**上亮下淡**渐变（ramp，非灰）+ 半个点宽 + 低透明度（0.45），即「轻量微光」 |
| 圆角 | `Radius.menuPanel`(16) + `.continuous`（squircle） |
| 阴影 | **系统窗口阴影**（`NSPanel.hasShadow` + `invalidateShadow()`）：多层弥散、随外观自适应 |
| 动效 | 从屏幕边缘 ease-out 滑入（0.26s，`nonactivatingPanel` 不抢焦点）；悬停只做 0.12s 淡入，不缩放不位移 |

## 4.7 浮动工具栏与就地文字

**浮动子工具栏（颜色 / 粗细）**：展开时**居中到刚才点的那个按钮下方**，而且是**悬浮的**——
它不能参与布局，否则会把内容区挤下去。

- 截图遮罩（AppKit 宿主）：按钮把 `midX` 报给 model（`OptionsAnchorReporter` +
  工具条坐标空间），`layoutToolbars()` 据此定位并夹进屏幕范围。
- 标注编辑器（纯 SwiftUI）：`anchorPreference(OptionsAnchorKey)` 记录颜色 / 粗细按钮的 bounds，
  `.overlayPreferenceValue` 把子工具栏画成 **overlay**（overlay 不参与布局，结构上就不可能挤动画布），
  `optionsBarCenterX/Y` 负责「居中到按钮 + 夹进窗口」，原地模式（工具栏在底部）改贴按钮上方。

不要靠右对齐到主栏边缘，也不要把它塞进 `VStack`（那会挤动内容）。

**就地文字输入**：点击处**原地**出现输入框，且**所见即所得**——

- 字体用渲染器同一套（Helvetica）、字号 = 写入标注的字号 ÷ 屏幕缩放；
- 文字颜色 = 标注颜色（不是固定白色）；
- **不铺底色、不加系统边框**（原来的黑底 + 白字 + 系统 bezel 是最丑的部分），
  只留一圈很细的同色边框（`borderWidth 1`，标注色 45% 透明度）标出编辑框；
- 框宽贴着文字宽度（避免吞掉旁边的点击），左上角对齐点击位置。

**图标尺寸**：工具条里的颜色圆点 `14`（不是 20）；动作按钮统一 `30×26`。

**焦点环**：`BarButton` 全部 `.focusEffectDisabled()`——工具条靠悬停 / 选中底表达状态，
系统那圈蓝色焦点环只会打架。

## 4.3 权限引导（引导向导）

`OnboardingView` 是四步向导（欢迎 → 屏幕录制权限 → 快捷键 → 完成），排版照参考项目的
Onboarding：

- **hero**（居中）：`heroMark` 60×60（第 1 步是 App 图标，其余是 30pt 字形 +
  `Circle().fill(tint.opacity(0.14))`）+ 标题 `.title2.weight(.bold)` +
  副标题 `.callout` + `.secondary` + 居中。**每一步一个自己的字形**，别两步共用。
- **卡片**：`OnboardingCard`（`cardFill` + `cardStroke` + `Radius.card`）内含
  `OnboardingRow`（20pt 图标槽 + 标题 `.body` + 副标题 `.caption` + 尾部控件，
  padding `xl`/`lg`）与 `OnboardingDivider`（缩进到与标题对齐）。
  状态用 `OnboardingStatusBadge`（`0.14` 透明度胶囊）。
  这是引导页**自己的**卡片，设置面板用 stock `Form` 分组，两者不共用。
- **底部**：7pt 步骤圆点（当前 `Color.primary`，其余 `opacity(0.2)`）+
  `上一步`（plain secondary）/ `稍后` / 主按钮（`.borderedProminent` + `.controlSize(.large)`
  + `.keyboardShortcut(.defaultAction)`）。
- **窗口**：`OnboardingWindowController` 用 `[.titled, .closable, .miniaturizable,
  .fullSizeContentView]` + 透明标题栏 + `isMovableByWindowBackground`；
  内容 `.padding(.top, xs)`（标题栏自己还有 32pt，得让开红绿灯）、
  `[.horizontal, .bottom]` 各 `xxl`；顶部 `sheen → clear` 的 `LinearGradient`
  `.ignoresSafeArea()`。
- **高度自适应**：视图 `.fixedSize(horizontal: false, vertical: true)` +
  `onGeometryChange` 量理想高度 → `window.fit(height:)`（补回标题栏高度、
  保持上边缘不动），每一步不裁不撑。

## 4.4 权限：现读 + 轮询 + 明确出口

参考项目的做法（`Platform/Permissions.swift` + 设置面板里的 1 秒 `Timer.publish`）：
**每次读活值，不做启动时快照**；界面自己轮询，用户主动了还能「重新检测」。

Jietu 的屏幕录制比辅助功能多一层限制，因此额外处理：

- `ScreenCapturePermission.isGranted` = `CGPreflightScreenCaptureAccess()`，**现读不缓存**。
- `wasGrantedAtLaunch` 由 `AppDelegate` 在 `applicationDidFinishLaunching` **最前面**
  `recordLaunchState()` 记一次——这是判断「授权是否晚于本次启动」的基准。
  `needsRelaunch = !wasGrantedAtLaunch && isGranted`。
- **截图入口不再用启动时快照**：`requireScreenCapturePermission()` 每次现读，
  不可用就打开权限引导（引导页有实时状态 + 两个出口）。
- **两个出口**：`重新检测`（现读一次）与 `重启 Jietu`。
  后者在 `needsRelaunch`，或「这次会话里引导过授权但状态仍未变」时出现
  （macOS 对屏幕录制的授权在授权时的那个进程里不生效，只有重启才可靠）。
- 引导页与设置页的权限分区都**1 秒轮询 + `NSApplication.didBecomeActiveNotification`
  时立刻复查**，从系统设置切回来不用等下一拍。
- 截图失败时 `CaptureError.suggestsRelaunch` 决定弹窗的首个按钮是
  「重启 Jietu」还是「打开系统设置」。
- **列表里看不到本 App 时的唯一出口是拖拽授权**（见 4.4.1）：不提供
  `tccutil reset` 那类「清记录重来」的入口——它会清掉当前**已经生效**的授权，
  代价大于收益。菜单栏给「拖拽授权「屏幕录制」…」与「重启 Jietu」；
  设置页权限分区合并成一个「拖拽授权…」；权限引导的主按钮同样走拖拽。

### 4.4.1 拖拽授权（对齐 PermissionFlow 的做法）

问题：系统设置「屏幕录制」那一栏**只列申请过的 App**，自签名 / Debug 构建经常压根不出现，
`tccutil reset` 也救不回来。但那一栏**接受拖入**——把 `.app` 拖进去就等于手动加入并授权。

`PermissionDragController`（`UI/Permissions/`）实现这套流程：

- `present()`：`CGRequestScreenCaptureAccess()`（没问过会弹窗并注册）→ 打开「屏幕录制」面板
  → 浮出 `PermissionDragPanel`。
- `PermissionDragPanel`：`[.borderless, .nonactivatingPanel]`、`level = .floating`、
  不成为 key/main（不抢系统设置的焦点）；`hostingView.sizingOptions = []` 让
  `setFrame` 成为几何的唯一来源，否则 SwiftUI 的 intrinsic size 会把定位推翻。
- 卡片 `AppBundleDragCard`：`NSDraggingSource` + Finder 风格的多类型 pasteboard 载荷
  （`.fileURL` / `.URL` / `NSFilenamesPboardType` / `promised-file-url` / `.string`），
  否则系统设置不收。拖拽开始时面板 `ignoresMouseEvents = true` 并变淡，
  drop 才能落到下面的列表里。
- 定位：**用 `CGWindowList` + owner pid 反查 `com.apple.systempreferences`**
  （`SystemSettingsWindow`），而不是参考实现的 AX 观察——**不用多要辅助功能权限**，
  也不受系统语言影响。面板贴在系统设置窗口下方、对齐右侧内容区（让开 230pt 侧栏），
  0.4 秒轮询跟随，窗口关掉约 3 秒后自动收工。
- 外观走参考项目的**浮动面板玻璃**：`.glassPanel()`（静态 `.regular` + `Radius.menuPanel`，
  不描边，与 `PopoverMenu` / `NoteSwitcherView` 同配方）；里面的卡片是 `controlSurface`
  的槽，头部两个按钮用 `BarIconButton`，底部动作用 `GlassButton`——全是设计系统组件。

## 4.5 构建渠道（Debug = dev）

Debug 是独立渠道，Debug 配置里 `PRODUCT_NAME = "Jietu Dev"`、
`PRODUCT_BUNDLE_IDENTIFIER = com.ixxxxoooo.jietu.dev`、`PRODUCT_MODULE_NAME = Jietu`
（固定，否则 `@testable import Jietu` 会断），`JietuTests` 的 `TEST_HOST` 同步指向
`Jietu Dev.app/Contents/MacOS/Jietu Dev`。

- 独立 bundle id = 独立 TCC 授权 / 偏好 / 登录项，本地调试不污染正式版。
- `AppIdentity`（`Core/AppIdentity.swift`）暴露 `displayName` / `isDevChannel` /
  `bundleIdentifier`；设置页「权限 › 授权对象」与权限引导都会显示当前身份，
  dev 渠道额外带一个 `accent` 描的 **dev** 药丸，照着在系统设置里勾选即可。
- `Config/Info.plist` 的 `CFBundleDisplayName = $(PRODUCT_NAME)`，所以系统设置的
  「屏幕录制」列表里 Debug 显示为 **Jietu Dev**。
